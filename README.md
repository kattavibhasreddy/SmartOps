# SmartOps - Incident Management Platform

A microservices-based incident management and workflow tracking platform.

## Architecture

SmartOps consists of four backend microservices and a React frontend, orchestrated via Docker Compose:

1. **gateway** (Port 8080): Express API Gateway using `http-proxy-middleware`. Handles JWT verification and routes requests.
2. **auth-service** (Port 4001): Manages users, roles, and issues JWT access and refresh tokens.
3. **incident-service** (Port 4002): Manages incident CRUD, assignment, status transitions, and audit history.
4. **notification-service** (Port 4003): Manages in-app notifications generated by incident events.
5. **frontend** (Port 3000): React + Vite + TypeScript application.
6. **postgres** (Port 5432): Single PostgreSQL container with separate schemas (`auth`, `incidents`, `notifications`) for each service.

## Prerequisites

- Docker and Docker Compose
- Node.js (for running migrations or seed scripts locally, though they can be run in the containers)

## Setup and Running

1. **Start the infrastructure**:
   ```bash
   docker compose up --build -d
   ```
   This command builds all images and starts the PostgreSQL database and all services. The database will automatically initialize schemas via `postgres-init/init.sql`.

2. **Run Migrations**:
   The containers run `npm start` by default. You need to run migrations inside each service to create the tables.
   ```bash
   docker exec -it smartops-auth npm run migrate
   docker exec -it smartops-incident npm run migrate
   docker exec -it smartops-notification npm run migrate
   ```

3. **Seed the Database**:
   You can run the seed script locally from the `scripts` folder (requires Node.js):
   ```bash
   cd scripts
   npm install
   node seed.js
   ```

4. **Access the Application**:
   - Frontend: http://localhost:3000
   - API Gateway: http://localhost:8080/api

## Development Notes

Each service has its own `.env` file that is loaded by Docker Compose. If you run the services locally outside of Docker, make sure to copy `.env.example` to `.env` and adjust the `DB_HOST` to `localhost`.
